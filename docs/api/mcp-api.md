# MCP API

The stdio and Streamable HTTP transports expose `workspace.list_files`, `workspace.read_file`, `workspace.write_file`, `workspace.delete_file`, `workspace.move_file`, `workspace.create_directory`, `scope_map.scan`, `context.get_domain_language`, and `context.build_task_context`. When directory documentation sources are configured, they also expose `documentation_source.preview`, `documentation_source.apply`, `documentation_source.sync`, and operator-approved `documentation_source.cutover`; all operations delegate to the same services as REST. Active mirrors reject general file mutations with `MIRROR_DOCUMENT_READ_ONLY`; successful cutover makes the selected copies managed and writable.

`abcm://map` returns the default workspace agent projection. `scope_map.scan` returns a safe revision summary with aggregate index counts; internal file, document, and executable-resource paths are not serialized. File reads use base64 to preserve exact bytes. The HTTP endpoint is `/mcp`; see [MCP Streamable HTTP API](mcp-http-api.md) and the [Obsidian integration guide](../integrations/obsidian.md).

`context.get_domain_language` accepts a workspace/project anchor and optional role id. It pins one MapRevision, merges workflow and project convention metadata, and returns a short-lived bootstrap bound to the configured principal and source checksums.

`context.build_task_context` requires that bootstrap id plus `roleId`, `taskType`, and `goal`. Optional canonical language, path hints, skill/document links, budget profile, and execution binding refine the build. The tool resolves the path and connected skills internally, materializes mandatory documents before optional candidates, and returns only the bounded ContextBundle. Each selected document records stable reasons, projection, checksum, and token estimate. The body-free ContextFingerprint is written below `.abcm/artifacts/plans/<plan-id>/context-fingerprints`; the full ScopeMap is never inserted into the response.
